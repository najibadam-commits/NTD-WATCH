# Integration boundaries

NTD-WATCH is an internal innovation proposal and functional prototype. It is **not integrated with anything**. This document lists the six places where an integration would sit, what each would carry, and the honest current state. **No boundary below is implemented as a live integration.** Where the prototype has a seam, that seam is the mock API and the `api-contract` package.

Status words: **SIMULATED** = a mock or seed stands in. **FUTURE** = nothing exists. **NOT CONNECTED** = no live link to any external system (true of every row below). Whether any integration should be built at all is an open Stage 6 question (outcome PROCEED, MODIFY, INTEGRATE, STOP or INCONCLUSIVE is not yet decided).

## How the prototype keeps the seams visible

- **One API contract** (`packages/api-contract`) lists every route, method, path and the permission it needs. A real backend would implement this contract.
- **One shared aggregation layer** (`packages/programme`) turns records into every programme figure. A real source would feed the same functions.
- **One mock server** (`apps/web/src/mock`) is the only place that stores data. Swapping it for a real server is the intended path.
- **The capability register** (`packages/domain/src/capabilities.ts`) is shown on the admin Settings page, so a viewer can see REAL, SIMULATED and FUTURE side by side.

## What would have to be true before any boundary becomes real

Stakeholder evidence from the Stage 6 validation plan, a written privacy and data-protection position, a named owner for each interface, and a sponsor decision on the Stage 6 outcome. None of these exists yet.
